# Domain model

The rules live in `packages/domain`, a dependency-free TypeScript package. Every function is pure: callers pass the actor, the current instant, and any stored data the rule needs, and get back new values or a `DomainError`.

## Entities

### Claim

| Field                         | Notes                                                                     |
| ----------------------------- | ------------------------------------------------------------------------- |
| `claimId`                     | Generated by the server.                                                  |
| `employeeId`                  | The owner; always the actor who created the claim.                        |
| `assignedManagerId`           | Copied from the owner's profile at each submission.                       |
| `categoryId`                  | Optional while drafting.                                                  |
| `amount`                      | `{ amountMinor, currency }`: integer minor units and an ISO-style code.   |
| `expenseDate`                 | Calendar date `YYYY-MM-DD`, not in the future.                            |
| `merchant`, `businessPurpose` | Trimmed text, up to 120 and 500 characters.                               |
| `receipt`                     | Optional receipt metadata (below).                                        |
| `status`                      | See the lifecycle.                                                        |
| `version`                     | Optimistic concurrency version, starting at 1 and incremented per change. |
| `createdAt`, `updatedAt`      | ISO 8601 instants.                                                        |
| `submittedAt`, `reviewedAt`   | Set on submission and on approval or rejection.                           |

Drafts may be incomplete. All fields except the receipt are required to submit.

### Category

`categoryId`, `name`, `active`, `currency`, `maxAmountMinor` (inclusive limit), `receiptRequiredAboveMinor`, plus `version`, `createdAt`, `updatedAt`, and `updatedBy`. Only administrators create or change categories.

### Receipt

Storage-neutral metadata recorded on the claim: `receiptId`, sanitized `fileName`, `contentType` (`application/pdf`, `image/jpeg`, or `image/png`), `sizeBytes` (1 byte to 10 MB), lower-case hex `checksumSha256`, and `attachedAt`.

An `UploadedReceipt` is what the server measured when the file arrived, plus its `ownerId` and, once used, `attachedClaimId`.

### Claim history entry

Immutable: `claimId`, `version` (the claim version it produced), `action`, `fromStatus`, `toStatus`, `actorId`, `occurredAt`, and an optional `comment`. Actions are `CREATE`, `UPDATE`, `ATTACH_RECEIPT`, `REPLACE_RECEIPT`, `REMOVE_RECEIPT`, and the six lifecycle actions. Every accepted claim mutation produces exactly one entry, stored together with the claim. The only way history is removed is when an owner deletes a draft that was never submitted, which removes the draft and its history together.

### Actor

`userId`, `displayName`, `roles` (`EMPLOYEE`, `MANAGER`, `ADMIN`), and `managerId` where the user has one. Actors are always loaded from the user directory on the server.

## Lifecycle

```text
DRAFT --SUBMIT--> SUBMITTED --START_REVIEW--> UNDER_REVIEW
UNDER_REVIEW --APPROVE--> APPROVED --MARK_PAID--> PAID
UNDER_REVIEW --REJECT--> REJECTED --REOPEN--> DRAFT
```

All other transitions are rejected with `INVALID_TRANSITION`. A rejected claim must be reopened to `DRAFT` before it can be edited and resubmitted.

## Authorization

| Operation                                   | Who                                                                                                           |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Create a claim, upload a receipt            | Users with the `EMPLOYEE` role.                                                                               |
| Edit a draft, attach/replace/remove receipt | The owner, only while `DRAFT` (`CLAIM_NOT_EDITABLE` otherwise).                                               |
| Delete a draft                              | The owner, only while `DRAFT` and only if it was never submitted (`CLAIM_NOT_DELETABLE` for reopened drafts). |
| Submit, reopen                              | The owner.                                                                                                    |
| Start review, approve, reject               | The assigned manager, never on their own claim.                                                               |
| Mark paid                                   | An administrator, never on their own claim.                                                                   |
| Manage categories                           | Administrators.                                                                                               |
| Delete a category                           | Administrators, only when no claim uses it (`CATEGORY_IN_USE` otherwise).                                     |
| View a claim, its history and receipt       | The owner, the assigned manager, and administrators.                                                          |

A claim the actor cannot view is reported as not found, so its existence is not revealed.

## Submission policy

Submission and resubmission re-evaluate the current category, so a draft cannot bypass a limit that changed after it was written. A claim can be submitted only when:

- category, amount, expense date, merchant, and business purpose are present and valid;
- the category exists and is active;
- the amount's currency matches the category currency;
- the amount does not exceed `maxAmountMinor` (equal is allowed);
- a receipt is attached when the amount is strictly above `receiptRequiredAboveMinor` (equal does not require one; a threshold of 0 requires one for every amount);
- the owner has a manager other than themselves.

All violations are reported together as `VALIDATION_FAILED` with one entry per field.

Inactive categories cannot be chosen for new claims or when changing a draft's category. A draft whose category is deactivated stays editable but cannot be submitted until its category is changed.

## Receipts

The server measures each upload itself: it checks the type against the file's leading bytes, enforces the size limit, computes the SHA-256 checksum, and sanitizes the file name. Attaching an upload requires the client to declare the content type, size, and checksum; the server checks them against what it stored, re-hashes the stored bytes, and only lets the owner attach their own unused upload to their own draft.

## Concurrency and idempotency

Every mutation names the version it expects. A stale version, or a concurrent write that lands first, fails with `VERSION_CONFLICT` instead of overwriting the newer data. Retryable requests carry an `Idempotency-Key`; a retry returns the original response and never applies the change twice (see [the API](api.md)).
